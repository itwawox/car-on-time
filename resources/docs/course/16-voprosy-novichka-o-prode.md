# Вопросы новичка о проде

Короткие ответы на то, что обычно непонятно, когда впервые запускаешь сайт.

## Файлы и картинки

**Куда загружать фото машин?**
Через админку того сайта, где они нужны: **Автопарк → Автомобили** → машина → фото. Файлы сами лягут на сервер в `storage/app/public`.

**А если картинок много — можно залить пачкой?**
Да, `rsync` в `storage/app/public`, но только **вместе с базой** с той же копии сайта. Без базы сайт не знает, чьё это фото (урок «База и картинки на тестовом сайте»).

**Можно положить картинку прямо в `public` на сервере через панель?**
Нет. Каждая выкладка делает `public` на сервере точной копией проекта и удаляет лишнее. Постоянные картинки дизайна (логотип, иконки) — в папку `public/` проекта на компьютере → коммит → выкладка.

**Картинки на сайте не открываются (404).**
На сервере: `/opt/php/8.4/bin/php artisan storage:link`. Команда создаёт ссылку `public/storage` → `storage/app/public`. Выкладка делает это сама, но после ручных переносов бывает нужно.

**При переезде на другой домен картинки сломаются?**
Нет. Адреса хранятся без домена (`/storage/12/solaris.jpg`) и работают на любом.

## База данных

**Где физически лежит база?**
На сервере MySQL хостинга, отдельно от файлов сайта. Увидеть глазами можно в панели reg.ru → **phpMyAdmin**.

**Почему у базы на хостинге другое имя, чем на компьютере?**
reg.ru добавляет к имени логин аккаунта. Сайт берёт имя из своего `.env`, а внутри копии базы имени нет — копию можно загрузить в базу с любым именем.

**Можно залить базу через phpMyAdmin, а не командой?**
Можно: phpMyAdmin → выбрать базу → **Импорт** → файл `.sql` (распакованный из `.sql.gz`). Для больших баз команда `gunzip -c … | mysql …` надёжнее: у phpMyAdmin есть ограничение на размер файла.

**Что за `migrate`? Его надо запускать?**
Миграции — изменения структуры базы (новая таблица, новое поле). Выкладка запускает `migrate --force` сама. Руками — только после загрузки копии базы (так написано в уроках).

**Почему нельзя `migrate:fresh`, `migrate:refresh`, `db:wipe`, `db:seed` на сервере?**
Первые три **удаляют все таблицы** со всеми заявками. `db:seed` заливает тестовые данные поверх настоящих. На сервере — никогда.

## .env и ключи

**Что такое `.env` и почему его нет в GitHub?**
Файл с настройками конкретной копии сайта: адрес, пароль базы, ключ шифрования. Репозиторий публичный — пароли туда нельзя. У каждого сайта свой `.env`, создаётся руками один раз.

**Где хранить копию `.env` и все пароли от хостинга?**
В менеджере паролей (приложение macOS «Пароли», Bitwarden или 1Password), отдельная запись на каждый сайт. Что именно записать — урок «Первый запуск тестового сайта», шаг 0. В файлы проекта и в GitHub — никогда: репозиторий публичный.

**Что будет, если потерять или поменять `APP_KEY`?**
Сотрудники войдут (пароли хранятся иначе), но все посетители разлогинятся, а ключи интеграций перестанут расшифровываться — интеграции тихо перестанут работать. Лечение — ввести ключи заново в **Интеграции → Интеграции**. Поэтому `APP_KEY` после запуска не меняют.

**Зачем разные `APP_KEY` на тестовом и боевом?**
Чтобы утечка тестового сайта не раскрыла боевые ключи CRM, SMS и оплаты. И чтобы тестовый сайт с копией боевой базы физически не мог отправить SMS клиенту.

**`APP_DEBUG=true` на сервере — можно, чтобы видеть ошибки?**
Нет, даже на тестовом: при ошибке любой посетитель увидит пароли из `.env`. Ошибки смотрите в журнале (ниже).

## Когда что-то не работает

**Белая страница или «Server Error 500».**
Смотрим журнал ошибок:

```bash
ssh u1111111@server111.hosting.reg.ru "tail -n 50 car-on-time/storage/logs/laravel.log"
```

Последняя ошибка в журнале обычно прямо называет причину: файл, строку и что пошло не так.

**Сайт без оформления: голый текст, нет стилей.**
Не собраны стили или сайт открыт не из папки `public`. Проверьте корневую директорию в панели (должна кончаться на `/public`) и что последняя выкладка в **Actions** зелёная.

**Поправил — а на сайте по-старому.**
По порядку:

1. Выкладка в **Actions** закончилась и зелёная?
2. Обновите страницу с очисткой кэша: Cmd + Shift + R.
3. На сервере: `/opt/php/8.4/bin/php artisan optimize:clear && /opt/php/8.4/bin/php artisan optimize`.

**«Страница устарела» / ошибка 419 при отправке формы.**
Истекла сессия или `APP_URL` в `.env` не совпадает с адресом (http вместо https, с `www` и без). Сверьте `APP_URL` с адресом в браузере.

**Заявки не уходят в Битрикс24 или Telegram.**

1. **Интеграции → Журнал обмена** — там ошибка от сервиса.
2. Работает ли CRON: `cd car-on-time && /opt/php/8.4/bin/php artisan schedule:list`.
3. Не выключены ли интеграции: `/opt/php/8.4/bin/php artisan integrations:status`.

**Выкладка остановилась: «на хостинге APP_URL=…, а выкладываем для …».**
Это защита: секреты среды в GitHub указывают не на тот сервер. Сравните `DEPLOY_URL` в **Settings → Environments** с `APP_URL` в `.env` на сервере.

## Разное

**Можно поправить файл прямо на сервере через панель?**
Нет. Следующая выкладка вернёт файл как в GitHub. Все правки кода — через компьютер и GitHub.

**Как дать клиенту доступ в админку?**
**Интеграции → Сотрудники** → создать, выбрать роль. Выключить доступ — там же, переключатель «Доступ открыт».

**Как закрыть тестовый сайт от посторонних?**
Поисковики его уже не видят (`robots.txt`). Защиту паролем через панель хостинга **не включайте**: она пишет файл `.htaccess` в папку `public`, а выкладка его перезапишет — сайт может перестать открываться. Если нужна защита паролем — попросите разработчика сделать её в коде.

**Сколько ждать, пока заработает новый домен или поддомен?**
Обычно 15–60 минут, иногда до суток. Проверка: `dig +short dev.void-web.ru`.

**SSL-сертификат платный?**
Нет, Let's Encrypt в панели reg.ru бесплатный и продлевается сам.

**Какая версия сейчас на сайте?**
Внизу любой страницы админки: «Версия 7c6caea · ветка dev · выложена … · сравнить с GitHub». Подробно — урок «Жизнь после запуска», раздел «Везде ли актуальная версия».

**Сломал боевой сайт — что делать первым?**
Откатить код на прошлую версию (урок «Жизнь после запуска»), и только потом разбираться. Клиентам важнее работающий сайт, чем быстрое исправление.
