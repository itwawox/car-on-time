# Всё вместе: порядок работы и шпаргалка

## Три контролёра

| Кто | Что проверяет | Аналогия |
|---|---|---|
| **Pint** | оформление кода | корректор |
| **Larastan** | ошибки, видные без запуска | инженер, который читает чертёж |
| **Pest** | что сайт правда работает, как задумано | испытатель, который пробует всё руками |

Каждый ловит своё, поэтому нужны все три.

## Порядок любого изменения

1. **Ветка.** Никогда не работаем прямо в `main`:

```bash
git checkout -b fix/nazvanie-zadachi
```

2. **Изменение** кода.
3. **Тест**: новый, если поменялось поведение. Если это баг — сначала красный тест, потом исправление.
4. **Проверки** — по порядку:

```bash
./vendor/bin/pint      # поправит оформление
./vendor/bin/phpstan   # ошибок быть не должно
./vendor/bin/pest      # все тесты зелёные
```

Или одной командой, в режиме проверки, как в GitHub:

```bash
composer check
```

Если меняли CSS или JS, ещё:

```bash
npm run build
```

5. **Документация**: если изменение влияет на настройку или работу сайта — поправить раздел в `resources/docs/developers`.
6. **Коммит и отправка:**

```bash
git add .
git commit -m "Что сделано, по-русски"
git push -u origin fix/nazvanie-zadachi
```

7. **Pull Request** на GitHub.
8. **GitHub Actions** сам запускает все проверки. Смотреть здесь: https://github.com/itwawox/car-on-time/actions.
   - зелёная галочка ✓ — всё прошло, можно вливать;
   - красный крестик ✗ — нажмите на запуск, откройте красный шаг («Тесты (Pest)», «Статанализ (Larastan)»…) и прочитайте ошибку, как в уроках 4 и 8.
9. **Вливаем** только с зелёной галочкой. После вливания в `main` сайт выкладывается на хостинг автоматически.

## Что проверяет GitHub

Файл `.github/workflows/tests.yml`, шаги по порядку:

1. устанавливает библиотеки и собирает стили;
2. Pint (`--test`);
3. Larastan;
4. Pest;
5. `composer audit` — нет ли известных уязвимостей в PHP-библиотеках;
6. `npm audit` — то же для JS-библиотек.

Выкладка (`deploy.yml`) запускает этот же набор и **не выкладывает сайт**, если хоть что-то красное.

## Шпаргалка

| Хочу | Команда |
|---|---|
| Все тесты | `./vendor/bin/pest` |
| Один файл тестов | `./vendor/bin/pest tests/Feature/PromoCodeTest.php` |
| Тесты по слову в названии | `./vendor/bin/pest --filter="promo"` |
| Создать тест | `php artisan make:test --pest NazvanieTest` |
| Поправить оформление | `./vendor/bin/pint` |
| Найти ошибки без запуска | `./vendor/bin/phpstan` |
| Всё сразу, как в GitHub | `composer check` |
| Собрать стили и скрипты | `npm run build` |
| Какая у меня ветка, что изменено | `git status` |
| Отменить изменения в файле | `git checkout путь/к/файлу` |

## Попробуйте сами

Запустите `composer check` и дождитесь конца. Должно быть три зелёных результата подряд: Pint без замечаний, `[OK] No errors` от Larastan и `passed` от Pest.
