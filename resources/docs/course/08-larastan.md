# Larastan — поиск ошибок без запуска

## Что это

Тесты **запускают** код и смотрят, что получилось. **Larastan** работает иначе: он **читает** код, как инженер читает чертёж, и ищет места, где что-то не сходится. Например:

- обращение к полю, которого у модели нет;
- переменная используется, но нигде не задана;
- функция ждёт число, а ей передают текст;
- метод вызывают у значения, которое может быть пустым (`null`).

Larastan — это PHPStan (анализатор для любого PHP) плюс знания о Laravel: он понимает модели, связи, фасады.

## Зачем, если есть тесты

Тесты проверяют только то, что в них написано. Larastan просматривает **весь** код в `app`, `routes` и `database/factories`, в том числе места, до которых тесты не доходят.

## Реальный баг, который он нашёл

В «Умный поиск → Настройки поиска» можно задать, насколько важно совпадение в названии, марке и других полях. Настройка **не работала**: в `app/Support/Search/SmartEngine.php` веса читались в переменную `$weights`, но внутрь функции, которая считала оценку, переменная не передавалась. Там она была пустой, и всегда брались значения по умолчанию.

Larastan сообщил:

```text
 ------ -----------------------------------------------
  Line   app/Support/Search/SmartEngine.php
 ------ -----------------------------------------------
  295    Undefined variable: $weights
 ------ -----------------------------------------------
```

Исправление — одно слово: передать переменную внутрь функции (`use (&$docs, $weights)`). Чтобы баг не вернулся, добавили тест `SearchWeightsTest.php`.

## Как читать ошибку

```text
  Line   app/Models/Booking.php
  42     Access to an undefined property App\Models\Car::$colour.
```

- `app/Models/Booking.php` — файл;
- `42` — строка;
- дальше — что не так: «обращение к несуществующему полю `$colour` у модели `Car`». Скорее всего, опечатка — поле называется `color`.

## Уровни строгости

У PHPStan уровни от 0 (самые грубые ошибки) до 10 (придирается ко всему). **У нас уровень 5** — золотая середина: ловит настоящие ошибки и не требует описывать тип каждой переменной.

Настройки — в файле `phpstan.neon` в корне проекта: уровень, папки для проверки.

## Baseline — список старых замечаний

Когда Larastan подключили, в старом коде он нашёл несколько десятков замечаний. Исправить всё сразу нельзя, поэтому их записали в файл `phpstan-baseline.neon`: «эти замечания известны, пока не показывать».

Правила:

- **новые** ошибки в baseline **не добавляем** — исправляем причину;
- не глушим проверку комментарием `@phpstan-ignore`;
- baseline со временем должен **уменьшаться**: тронули старый файл — исправили его замечания.

## Команды

```bash
./vendor/bin/phpstan
```

Хороший результат:

```text
 [OK] No errors
```

## Попробуйте сами

1. Откройте `app/Support/Phone.php` и в любом месте функции напишите `return $nothing;`.
2. Запустите `./vendor/bin/phpstan` — он покажет `Undefined variable: $nothing` с номером строки.
3. Отмените изменение: `git checkout app/Support/Phone.php`.
