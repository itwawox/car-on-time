# Первый запуск тестового сайта dev.void-web.ru

Делается **один раз**, займёт 1–2 часа. В примерах:

- `u2222222` — логин второго аккаунта reg.ru (где будет тестовый сайт); подставьте свой, он в письме от reg.ru и в панели;
- `server222.hosting.reg.ru` — адрес его сервера (панель хостинга → «Информация» или «Доступ по SSH»);
- папка сайта на хостинге — `car-on-time-dev`.

Все команды с `ssh` вводятся **на вашем компьютере** в Терминале. Команды после входа по `ssh` выполняются **уже на сервере**.

## Шаг 0. Карточка доступов — куда записывать данные

Пока вы проходите шаги, появятся логины, пароли и адреса. Сразу записывайте их в **менеджер паролей**: встроенное приложение macOS «Пароли», Bitwarden (бесплатный) или 1Password. Заведите отдельную запись для каждого сайта.

**Запись «Car on Time — тестовый (dev.void-web.ru)»:**

| Что | Пример | Откуда |
|---|---|---|
| Вход в личный кабинет reg.ru | email и пароль | при регистрации |
| Логин хостинга и адрес сервера | `u2222222`, `server222.hosting.reg.ru` | письмо от reg.ru, панель |
| Пароль хостинга (SSH и панель) | … | письмо от reg.ru |
| База: имя, пользователь, пароль | `u2222222_dev` | шаг 3 |
| Файл `.env` целиком | вложение или заметка | шаг 8 |
| Где лежит ключ выкладки | `~/.ssh/dev-void-deploy` | шаг 5 |
| Админка: email и пароль владельца | … | шаг 12 |

Для боевого сайта заведите такую же запись (урок «Переезд на car-on-time.ru»).

**Никогда не записывайте доступы:**

- в файлы проекта — репозиторий на GitHub **публичный**, его может прочитать кто угодно;
- в `CLAUDE.md`, `PLAN.md`, документацию и этот курс;
- в заметки на рабочем столе и в мессенджеры.

В GitHub доступы вписываются только в одно место — **Secrets** в Settings → Environments (шаг 6). Они зашифрованы, их не видно даже вам.

Для запасной выкладки со своего компьютера доступы можно держать в файлах `deploy/.env.deploy` (боевой) и `deploy/.env.deploy.dev` (тестовый): git их не видит, и в GitHub они не попадут. Как ими пользоваться — **Для разработчиков → Обновление боевого сайта**.

> **Нужно ли говорить пароли Claude?** Нет. Ему хватит логина и адреса сервера — это не секрет. Команды, которые спрашивают пароль (например, `ssh-copy-id`), запускайте в обычном приложении «Терминал» и вводите пароль сами — так он не попадёт в переписку. Результат можно потом скопировать Claude.

## Шаг 1. Поддомен dev.void-web.ru

1. Панель хостинга → **«Сайты»** → **«Создать сайт»** → имя `dev.void-web.ru`.
2. Если домен `void-web.ru` обслуживается **в этом же** аккаунте reg.ru — поддомен заработает сам.
3. Если домен у **другого** хостинга или аккаунта — там, где управляете DNS домена `void-web.ru`, добавьте запись:
   - тип `A`;
   - имя `dev`;
   - значение — IP-адрес хостинга `u2222222` (панель → «Информация о хостинге» → IP).
4. Подождите: обычно 15–60 минут, иногда до суток. Проверка:

```bash
dig +short dev.void-web.ru      # должен показать IP хостинга
```

## Шаг 2. PHP 8.4 и лимиты загрузки

Панель → «Сайты» → `dev.void-web.ru` → **версия PHP 8.4**. Там же в настройках PHP:

- `upload_max_filesize = 10M`;
- `post_max_size = 48M`.

Без этих лимитов не загрузятся фото машин и документы клиентов.

## Шаг 3. База данных

Панель → **«Базы данных»** → **«Создать»**. Запишите в надёжное место (менеджер паролей):

- имя базы — например `u2222222_dev`;
- пользователя — часто совпадает с именем базы;
- пароль.

База пока **пустая** — таблицы создаст сама выкладка.

## Шаг 4. SSH

Панель → **«Доступ по SSH»** → включить. Проверка:

```bash
ssh u2222222@server222.hosting.reg.ru
/opt/php/8.4/bin/php -v        # PHP 8.4
which rsync mysqldump gzip     # все три должны найтись
exit
```

## Шаг 5. Ключ, чтобы GitHub мог заливать файлы

Для каждого хостинга — **свой** ключ:

```bash
ssh-keygen -t ed25519 -f ~/.ssh/dev-void-deploy -C "github-deploy-dev"
ssh-copy-id -i ~/.ssh/dev-void-deploy.pub u2222222@server222.hosting.reg.ru
ssh -i ~/.ssh/dev-void-deploy u2222222@server222.hosting.reg.ru "echo ok"
```

На вопросы первой команды просто нажимайте Enter. Вторая один раз спросит пароль хостинга. Третья должна ответить `ok` **без** пароля.

## Шаг 6. Среда staging в GitHub

https://github.com/itwawox/car-on-time → **Settings → Environments → New environment** → `staging`.

**Environment secrets** (кнопка «Add environment secret», по одному):

| Имя | Значение |
|---|---|
| `DEPLOY_HOST` | `server222.hosting.reg.ru` |
| `DEPLOY_USER` | `u2222222` |
| `DEPLOY_PATH` | `/var/www/u2222222/data/car-on-time-dev` |
| `DEPLOY_PHP` | `/opt/php/8.4/bin/php` |
| `DEPLOY_SSH_KEY` | вывод команды `cat ~/.ssh/dev-void-deploy` целиком, с первой до последней строки |

**Environment variables** → `DEPLOY_URL` = `https://dev.void-web.ru`.

Один раз для всего репозитория: **Settings → Secrets and variables → Actions → Variables** → `DEPLOY_ENABLED` = `true`.

> Путь `/var/www/u2222222/data/…` — для панели ISPmanager. Узнать свою домашнюю папку: `ssh u2222222@server222.hosting.reg.ru pwd`.

## Шаг 7. Ветка dev — первая выкладка

Всё, что попадает в ветку `dev`, GitHub сам выкладывает на тестовый сайт. Создадим её из ветки с новым сайтом:

```bash
cd ~/Herd/rentacar
git checkout feature/enterprise && git pull
git checkout -b dev
git push -u origin dev
```

GitHub → вкладка **Actions** → запуск «Выкладка на хостинг». Он **остановится** с сообщением «На хостинге нет файла .env» — это ожидаемо: файлы уже залиты, осталось настроить сайт.

## Шаг 8. Файл .env на сервере

```bash
ssh u2222222@server222.hosting.reg.ru
cd car-on-time-dev
cp .env.example .env
nano .env
```

Поменяйте строки (стрелки — перемещение; сохранить — Ctrl+O, Enter; выйти — Ctrl+X):

```dotenv
APP_ENV=staging
APP_DEBUG=false
APP_URL=https://dev.void-web.ru

DB_HOST=localhost
DB_DATABASE=u2222222_dev
DB_USERNAME=u2222222_dev
DB_PASSWORD=пароль-из-шага-3
```

- `APP_ENV=staging` закрывает сайт от поисковиков и отключает Метрику.
- `APP_DEBUG=false` — даже на тестовом: иначе при ошибке любой посетитель увидит пароли из `.env`. Ошибки смотрим в журнале (урок «Вопросы новичка о проде»).
- `APP_URL` **должен совпадать** с `DEPLOY_URL` из шага 6, иначе выкладка остановится.

Затем создайте ключ шифрования и выйдите:

```bash
/opt/php/8.4/bin/php artisan key:generate
exit
```

**Сохраните копию `.env`** в менеджер паролей. Без `APP_KEY` из этого файла не расшифровать ключи интеграций.

## Шаг 9. Выкладка до конца

GitHub → **Actions → «Выкладка на хостинг» → Run workflow**:

- среда — `staging`;
- что выложить — `dev`.

Теперь выкладка пройдёт полностью: создаст таблицы в пустой базе, соберёт кэши, откроет сайт.

## Шаг 10. Папка сайта → public, SSL

Сайт должен открываться из папки `public`, иначе в интернет будут видны служебные файлы.

**Если панель даёт менять корневую директорию:** «Сайты» → `dev.void-web.ru` → **Корневая директория** → `/var/www/u2222222/data/car-on-time-dev/public`.

**Если не даёт (так было у нас)** — ставим на место папки сайта **ярлык** (символическую ссылку) на папку `public`. Панель открывает сайт из `~/www/dev.void-web.ru` и не замечает подмены.

```bash
ssh u2222222@server222.hosting.reg.ru
cd ~/www
mv dev.void-web.ru dev.void-web.ru.old                       # старую папку не удаляем
ln -s ~/www/car-on-time-dev/public dev.void-web.ru           # ярлык: КУДА ведёт, потом ИМЯ
ls -la | grep dev.void-web.ru                                # проверка
exit
```

Проверка показывает стрелку: `dev.void-web.ru -> /var/www/u2222222/data/www/car-on-time-dev/public`. Откройте http://dev.void-web.ru — это уже наш сайт.

> **Надёжнее — одной строкой.** Если вставить команды пачкой, а вход по `ssh` не удастся, остальные строки выполнятся **на вашем компьютере** (у нас так и случилось: ярлык появился в папке проекта на Mac). Одна строка выполняется целиком на сервере или не выполняется вовсе:
>
> ```bash
> ssh u2222222@server222.hosting.reg.ru 'cd ~/www && mv dev.void-web.ru dev.void-web.ru.old && ln -s ~/www/car-on-time-dev/public dev.void-web.ru && ls -la | grep dev.void-web.ru'
> ```
>
> Как понять, где вы сейчас: на сервере строка приглашения начинается с логина хостинга (`u2222222@…`), на Mac — с вашего имени (`ivanromanov@…`).

Путь в ярлыке — это `DEPLOY_PATH` из шага 6 плюс `/public`. В примере код лежит в `~/www/car-on-time-dev`. Если вы выбрали `~/car-on-time-dev`, ярлык будет `ln -s ~/car-on-time-dev/public dev.void-web.ru`.

**Вернуть как было:**

```bash
cd ~/www
rm dev.void-web.ru                    # удаляется ТОЛЬКО ярлык, сайт цел
mv dev.void-web.ru.old dev.void-web.ru
```

> Удаляйте ярлык именно так: `rm` и имя **без** `/` на конце. Команды `rm -r` и `rm -rf` с `/` на конце могут удалить содержимое папки, на которую ведёт ярлык, — то есть сам сайт.

Когда сайт заработает, старую папку можно удалить: `rm -r ~/www/dev.void-web.ru.old`. В ней лежал проверочный файл `phpinfo`.

Затем в панели: **SSL-сертификат** (бесплатный Let's Encrypt) и **перенаправление на HTTPS**. Выпускайте после создания ярлыка.

Подробнее, в том числе как перенаправить ярлык на другую папку, — **Для разработчиков → Первая настройка хостинга reg.ru**, раздел 6.

## Шаг 11. CRON — каждую минуту

Панель → **Планировщик CRON → Создать задание**:

- команда: `/opt/php/8.4/bin/php /var/www/u2222222/data/car-on-time-dev/artisan schedule:run`;
- расписание: каждую минуту (`* * * * *`).

Без CRON не работают очередь, напоминания и ночные копии базы.

## Шаг 12. Владелец админки и выключенные интеграции

```bash
ssh u2222222@server222.hosting.reg.ru
cd car-on-time-dev
/opt/php/8.4/bin/php artisan user:owner ваш@email.ru --name="Иван"
/opt/php/8.4/bin/php artisan integrations:disable
exit
```

Первая команда один раз покажет пароль — сохраните его. Вторая выключает CRM, SMS и оплату: тестовые заявки не должны уходить настоящим клиентам и менеджерам.

## Проверка

- https://dev.void-web.ru открывается, есть замочек HTTPS. Машин пока нет — это нормально, база пустая (следующий урок).
- https://dev.void-web.ru/admin — вход работает.
- https://dev.void-web.ru/robots.txt показывает `Disallow: /` — поисковики сайт не видят.
- В админке **Интеграции → Интеграции** всё выключено.
