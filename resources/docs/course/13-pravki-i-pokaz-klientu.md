# Правки и показ клиенту

Тестовый сайт работает, клиент его смотрит и присылает замечания. Как вносить правки, чтобы ничего не потерять.

## Два вида правок

| Правка | Пример | Где делать |
|---|---|---|
| **Код** — как сайт выглядит и работает | «кнопка другого цвета», «убрать пункт меню», «новое поле в форме» | на компьютере → ветка `dev` → тестовый сайт сам обновится |
| **Данные** — что написано и загружено | «поменять цену», «другое фото машины», «исправить текст FAQ» | **в админке тестового сайта** |

Правило простое: **код правим на компьютере, данные — в админке того сайта, который потом станет боевым**. До запуска это тестовый сайт: всё, что клиент или вы поправите в его админке, при переезде уедет на `car-on-time.ru`.

## Правка кода: путь до тестового сайта

```bash
cd ~/Herd/rentacar
git checkout dev && git pull           # свежая ветка dev
git checkout -b fix/knopka-zayavki     # своя ветка для правки
# … правите код, проверяете на http://rentacar.test …
composer check                         # Pint, Larastan, тесты
git add .
git commit -m "Кнопка заявки: фирменный цвет"
git checkout dev
git merge fix/knopka-zayavki
git push                               # GitHub выложит на dev.void-web.ru
```

Через 3–5 минут правка на тестовом сайте. Следить — вкладка **Actions** на GitHub.

Если проверки упали (красный крестик), тестовый сайт **не тронут**: GitHub не выкладывает сломанный код.

## Если клиент правит в админке тестового сайта

Удобно: клиент сам меняет тексты и цены, вы видите результат сразу. Дайте ему доступ:

1. Админка тестового сайта → **Интеграции → Сотрудники** → создать.
2. Роль:
   - «Контент-редактор» — тексты, статьи, FAQ, акции;
   - «Менеджер» — машины, цены, заявки;
   - «Владелец» — всё, включая интеграции.
3. Отправьте клиенту адрес https://dev.void-web.ru/admin, email и пароль.

После запуска этот сотрудник переедет на боевой сайт вместе с базой. Если он там не нужен — снимите у него переключатель «Доступ открыт» в «Сотрудниках».

## Не смешивайте: правки данных на компьютере

Если поменять цену на `rentacar.test`, на тестовый сайт она **не попадёт**: у каждой копии своя база. Перенос базы с компьютера на тестовый сайт (прошлый урок) **затрёт** всё, что клиент поправил в админке тестового сайта.

Поэтому после первого наполнения данные меняем **только на тестовом сайте**.

## Утверждение: «заморозка»

Когда клиент говорит «всё хорошо, запускаем»:

1. Договоритесь о дне переезда.
2. С этого момента **никто не правит данные** на тестовом сайте: всё, что поменяется после копии, на боевой сайт не попадёт.
3. Правки кода можно продолжать: они выложатся на боевой сайт через ветку `main`.

Дальше — урок «Переезд на car-on-time.ru».
