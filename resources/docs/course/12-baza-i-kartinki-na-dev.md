# База и картинки на тестовом сайте

После первого запуска тестовый сайт пустой. Наполнить его можно двумя путями.

| Путь | Когда подходит |
|---|---|
| **А. Перенести с компьютера** | на `rentacar.test` уже есть машины, цены, фото — так у нас |
| **Б. Заполнить в админке** | начинаете с нуля |

## Куда загружать картинки — коротко

- **Фото машин, обложки, картинки в статьях** — через **админку** сайта. Они сами лягут в `storage/app/public` на сервере, а в базе появится запись, к какой машине относится фото.
- **Перенести пачкой** с другой копии сайта — `rsync` в папку `storage/app/public` **вместе с базой**.
- **Логотип, иконки, картинка для превью** — это часть кода: папка `public/` в проекте → коммит → выкладка.
- **Никогда не кладите файлы руками в `public/` на сервере.** Выкладка делает папку `public` на сервере точной копией проекта и **удаляет** всё лишнее. Не трогает она только `storage` и ссылку `public/storage`.

Почему фото без базы бессмысленны: файл `storage/app/public/12/solaris.jpg` лежит на диске, но только таблица `media` в базе знает, что это фото машины №5 и оно первое в галерее. Переносим **всегда вместе**.

## Путь А: с компьютера на тестовый сайт

### 1. Копия локальной базы

```bash
cd ~/Herd/rentacar
php artisan backup:database
ls storage/backups
```

Появится файл вида `db-2026-10-01_12-00-00.sql.gz` — сжатая копия базы. Это та же команда, что каждую ночь делает копии на сервере.

> Если пишет, что не найден `mysqldump`: откройте базу в TablePlus или другой программе для MySQL → Export → SQL и сожмите файл (`gzip файл.sql`).

### 2. Отправить копию на сервер

```bash
scp storage/backups/db-2026-10-01_12-00-00.sql.gz u2222222@server222.hosting.reg.ru:car-on-time-dev/storage/backups/
```

### 3. Загрузить в базу тестового сайта

```bash
ssh u2222222@server222.hosting.reg.ru
cd car-on-time-dev
/opt/php/8.4/bin/php artisan down
gunzip -c storage/backups/db-2026-10-01_12-00-00.sql.gz | mysql -u u2222222_dev -p u2222222_dev
```

`mysql` спросит пароль базы — он в `.env` (`DB_PASSWORD`). Посмотреть его: `grep DB_ .env`.

Старые таблицы тестового сайта заменятся таблицами с компьютера. Имя базы при этом **не важно**: в копии его нет.

**Без ввода пароля — так переносили мы.** Пароль берётся прямо из `.env` на сервере и нигде не показывается. Всё одной командой с вашего компьютера:

```bash
ssh -i ~/.ssh/dev-void-deploy u2222222@server222.hosting.reg.ru 'cd ~/www/car-on-time-dev
val() { grep -E "^$1=" .env | head -n1 | cut -d= -f2- | tr -d "\"" ; }
/opt/php/8.4/bin/php artisan down
gunzip -c storage/backups/db-2026-10-01_12-00-00.sql.gz | MYSQL_PWD="$(val DB_PASSWORD)" mysql -h "$(val DB_HOST)" -u "$(val DB_USERNAME)" "$(val DB_DATABASE)"
MYSQL_PWD="$(val DB_PASSWORD)" mysql -h "$(val DB_HOST)" -u "$(val DB_USERNAME)" "$(val DB_DATABASE)" -e "SELECT COUNT(*) AS cars FROM cars"'
```

- `val DB_PASSWORD` — достать из `.env` значение строки `DB_PASSWORD=…`;
- `MYSQL_PWD=…` — передать пароль программе `mysql` так, чтобы его не было видно ни на экране, ни в списке процессов;
- последняя строка — проверка: сколько машин теперь в базе тестового сайта.

### 4. Довести до порядка и открыть

```bash
/opt/php/8.4/bin/php artisan migrate --force
/opt/php/8.4/bin/php artisan integrations:disable
/opt/php/8.4/bin/php artisan optimize:clear
/opt/php/8.4/bin/php artisan optimize
/opt/php/8.4/bin/php artisan up
exit
```

- `migrate --force` добавит таблицы, если база с компьютера отстаёт от кода. Если всё свежее, напишет «Nothing to migrate».
- `integrations:disable` — обязательно: переключатели интеграций приехали из локальной базы.

### 5. Картинки

Картинки переносим программой **`rsync`** — она копирует папки между компьютерами через SSH. Ею же выкладка заливает код на сервер.

**Сначала пробный запуск** — ничего не копирует, только показывает, что будет сделано:

```bash
rsync -avzn --stats -e "ssh -i ~/.ssh/dev-void-deploy" \
  ~/Herd/rentacar/storage/app/public/ \
  u2222222@server222.hosting.reg.ru:www/car-on-time-dev/storage/app/public/
```

В конце вывода смотрите на `Number of files transferred` (сколько файлов поедет) и на строки `deleting` — их быть **не должно**.

**Потом по-настоящему** — та же команда без `n`:

```bash
rsync -avz --stats -e "ssh -i ~/.ssh/dev-void-deploy" \
  ~/Herd/rentacar/storage/app/public/ \
  u2222222@server222.hosting.reg.ru:www/car-on-time-dev/storage/app/public/
```

| Кусок | Что значит |
|---|---|
| `-a` | копировать как есть: подпапки, даты, права |
| `-v` | показывать каждый файл |
| `-z` | сжимать при передаче — быстрее |
| `-n` | пробный запуск, **ничего не менять** |
| `--stats` | итог: сколько файлов и байт передано |
| `-e "ssh -i …"` | ехать через SSH с ключом выкладки |
| `…/public/` — слэш на конце источника | взять **содержимое** папки. Без слэша на сервере появилась бы лишняя папка `public/public` |
| `u2222222@…:www/…/public/` | куда класть; путь после двоеточия — от домашней папки на сервере |

**Главное про безопасность `rsync`:**

- Повторный запуск **безопасен**: `rsync` передаёт только новые и изменённые файлы. Можно запускать сколько угодно раз.
- Без флага `--delete` `rsync` на сервере **ничего не удаляет**. С `--delete` удалит там всё, чего нет у вас. Для фото `--delete` **не используйте**.
- Сначала всегда `-n`, потом по-настоящему.

**Проверка после копирования** — сколько файлов на сервере (должно совпасть с компьютером):

```bash
find ~/Herd/rentacar/storage/app/public -type f | wc -l
ssh -i ~/.ssh/dev-void-deploy u2222222@server222.hosting.reg.ru 'find ~/www/car-on-time-dev/storage/app/public -type f | wc -l'
```

У нас было 472 файла, 38 МБ: фото 147 машин (оригинал и две уменьшенные копии) и обложки 10 статей. Перед переносом проверили, что каждый файл используется: у каждой папки с номером есть запись в базе, у каждой обложки — статья.

### 6. Проверка

- на https://dev.void-web.ru есть машины и фото;
- картинки открываются. Если 404 — выполните на сервере `/opt/php/8.4/bin/php artisan storage:link`.

## Что приезжает вместе с базой

- **Сотрудники админки** — ваш логин и пароль от `rentacar.test` теперь работают на тестовом сайте. Если пароль простой, смените его: **Интеграции → Сотрудники**.
- **Тестовые заявки** с компьютера — удалите в админке или оставьте для показа.
- **Ключи интеграций** зашифрованы локальным `APP_KEY`. На тестовом сайте другой ключ, и они не расшифруются. Интеграции тихо перестанут видеть ключи — для тестового сайта это как раз хорошо.

## Путь Б: заполнить в админке

Просто работайте в https://dev.void-web.ru/admin: добавляйте машины, загружайте фото, пишите тексты. Всё сохранится в базе и в `storage` тестового сайта, а при переезде переедет целиком (урок «Переезд на car-on-time.ru»).

## Попробуйте сами

После переноса откройте на тестовом сайте любую машину и сравните с `rentacar.test`: цены, фото и тексты должны совпадать.
