# Из чего состоит сайт

Сайт удобно представить как **ресторан**.

| В ресторане | На сайте | Где у нас |
|---|---|---|
| Зал, меню, официант | **Витрина** — страницы, которые видит клиент | `resources/views` (Blade), `resources/css`, `resources/js` |
| Кухня и повар | **Laravel** — программа на PHP, которая обрабатывает запросы | `app/` |
| Склад | **База данных** MySQL — машины, заявки, настройки | таблицы, описанные в `database/migrations` |
| Кабинет управляющего | **Админка Filament** — `/admin` | `app/Filament` |
| Курьер | **Очередь** — отправляет данные в Битрикс24, SMS и Telegram, не задерживая клиента | `app/Jobs` |
| Будильник | **Планировщик (cron)** — раз в минуту будит сайт: «есть дела?» | `routes/console.php` |

## Путь одной заявки

Клиент открыл карточку машины, выбрал даты и нажал «Оставить заявку». Вот что происходит:

1. **Браузер** отправляет форму на адрес `/zayavka`.
2. **Маршрут** в `routes/web.php` говорит: «этот адрес обрабатывает `BookingController`».
3. **Проверка данных**: телефон есть? Согласие отмечено? Если нет — клиент увидит понятную ошибку под полем.
4. **Расчёт цены** — всегда в одном месте, в `app/Services/QuoteCalculator.php`: аренда по сезонам, доставка, доп. услуги, промокод, залог.
5. **Запись в базу**: заявка сохраняется в таблицу `bookings`.
6. **Очередь**: сайт кладёт в очередь задания «отправить в Битрикс24», «отправить SMS», «сообщить в Telegram». Клиенту не нужно ждать, пока ответят чужие сервисы.
7. **Страница «Спасибо»** открывается сразу.
8. **Cron** раз в минуту запускает обработку очереди — курьер разносит задания. Если Битрикс24 не отвечает, в журнале интеграций появится ошибка, а заявка клиента всё равно сохранена.
9. **Менеджер** видит заявку в админке и в CRM.

## Почему так

- **Цена считается в одном месте.** Если бы карточка, каталог и заявка считали по-разному, клиент видел бы одну сумму, а менеджер другую.
- **Внешние сервисы — только через очередь.** Сбой SMS или CRM не должен ломать заявку клиента.
- **Тексты и цифры — в админке** (`Setting::get()`), а не в коде. Поменять телефон или залог можно без программиста.

## Два входа в сайт: браузер и artisan

У сайта на Laravel два входа, а внутри одна и та же программа.

| Вход | Кто пользуется | Как |
|---|---|---|
| **Браузер** | посетители, менеджеры | `https://car-on-time.ru/…` → файл `public/index.php` → Laravel показывает страницу |
| **Командная строка** | CRON, выкладка, разработчик | `php artisan команда` → файл `artisan` в корне проекта → Laravel выполняет команду и пишет ответ текстом |

`artisan` — это тот же сайт, только через служебный вход и без браузера: тот же код, та же база, те же настройки из `.env`. Примеры команд: `artisan migrate` (изменить структуру базы), `artisan backup:database` (копия базы), `artisan user:owner` (создать владельца админки).

## Расписание: как сайт сам делает дела по времени

Сайт должен каждую ночь делать копию базы, раз в минуту отправлять заявки в CRM, напоминать клиентам об аренде. Сам по себе он «спит»: просыпается, только когда кто-то открывает страницу.

Будит его **CRON** — будильник хостинга. В панели reg.ru стоит **одна** строка, каждую минуту:

```text
/opt/php/8.4/bin/php /путь/к/сайту/artisan schedule:run
```

Что происходит каждую минуту:

1. CRON запускает `artisan schedule:run` — «зайти на сайт через служебный вход».
2. Laravel загружается: читает `.env`, подключается к базе.
3. Встроенная в Laravel команда `schedule:run` открывает файл с расписанием — `routes/console.php`:

```php
Schedule::command('bookings:escalate')->everyMinute();   // напомнить в чат о заявках без ответа
Schedule::command('backup:database')->dailyAt('03:30');  // ночная копия базы
Schedule::command('documents:prune')->dailyAt('04:10');  // удалить документы клиентов по сроку
```

4. Сверяет часы: «сейчас 03:30 — делаю копию базы», остальное пропускает.

Посмотреть расписание на сервере: `php artisan schedule:list`. Звёздочки слева — пять полей CRON: минута, час, день месяца, месяц, день недели. Звёздочка значит «любое»: `* * * * *` — каждую минуту, `30 3 * * *` — каждый день в 03:30.

**Как понять, что CRON работает?** Админка → «Сводка» → блок **«Сайт»**: «Планировщик (CRON) — минуту назад» и время последней копии базы. Каждую минуту сайт ставит отметку «я проснулся», а сводка показывает, когда была последняя. Если карточка красная — CRON в панели хостинга не настроен или выключен.

**Откуда сервер знает расписание?** Из кода: выкладка заливает `routes/console.php` вместе со всем сайтом. CRON про копии базы и SMS ничего не знает — он только раз в минуту будит сайт.

**Это только в Laravel?** Идея общая, названия свои:

| Где | Как устроено |
|---|---|
| **Laravel** (у нас) | одна строка CRON → `schedule:run` → расписание в коде |
| **Symfony** | похоже: компонент Scheduler, расписание в коде |
| **WordPress** | `wp-cron`: запускается при заходах посетителей или одной строкой CRON |
| **Сайт без фреймворка** | каждая задача — отдельная строка в CRON, всё правится в панели хостинга |

Почему Laravel сделал так: расписание — часть программы. Оно хранится в git, одинаково на тестовом и боевом сайте, проверяется тестами. Чтобы поменять его, правят код и делают выкладку, а в панель хостинга не ходят.
