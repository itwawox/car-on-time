# Жизнь после запуска

Боевой сайт работает, клиенты оставляют заявки. Теперь главное — **ничего не потерять**.

## Правило, которое нельзя нарушать

> **Никогда не загружайте базу тестового сайта или компьютера на боевой сайт.**

После запуска в боевой базе настоящие заявки, клиенты, документы и оплаты. Загрузка любой другой копии **сотрёт их без возврата**. Данные теперь движутся только вниз: боевой → тестовый → компьютер.

## Как выпускать обновления

```text
компьютер                 тестовый сайт              боевой сайт
ветка fix/…  ──merge──▶   ветка dev  ──Pull Request──▶  ветка main
             (git push)   dev.void-web.ru   (Merge)     car-on-time.ru
```

1. Правка на компьютере в своей ветке, `composer check`.
2. Слить в `dev` и отправить (`git push`) → GitHub выложит на тестовый сайт.
3. Проверить на https://dev.void-web.ru, при необходимости показать клиенту.
4. GitHub → **Pull request** `dev → main` → зелёная галочка → **Merge**.
5. GitHub выложит на боевой: копия базы → режим обслуживания → файлы → миграции → сайт открыт. 3–5 минут.

Миграции (изменения структуры базы) применяются **сами** на обоих сайтах. Руками на сервере ничего запускать не нужно.

## Везде ли актуальная версия

Одна версия живёт в четырёх местах. Сравниваем по цепочке.

```text
компьютер  ──git push──▶  GitHub  ──выкладка──▶  dev.void-web.ru (ветка dev)
                                   ──выкладка──▶  car-on-time.ru  (ветка main)
```

**1. Компьютер и GitHub:**

```bash
cd ~/Herd/rentacar
git fetch            # узнать, что нового на GitHub (ничего не меняет)
git status -sb       # первая строка — расхождение
```

- `## dev...origin/dev` без скобок — совпадает;
- `[ahead 2]` — у вас 2 коммита, которых нет на GitHub, → `git push`;
- `[behind 3]` — на GitHub 3 новых коммита, → `git pull`;
- нет `...origin/` — ветка вообще не отправлена.

Все ветки сразу: `git branch -vv`.

**2. GitHub и сайт.** Внизу любой страницы админки сайта:

```text
Версия 7c6caea · ветка dev · выложена 15.10.2026 18:04 · сравнить с GitHub
```

Нажмите **«сравнить с GitHub»**:

- «There isn't anything to compare» или «identical» — на сайте последняя версия ветки;
- список коммитов — они уже в GitHub, но ещё не выложены. Посмотрите вкладку **Actions**: выкладка идёт или упала.

«Версия не записана» — это копия на компьютере или сайт выложен в обход скрипта выкладки.

**3. Тестовый и боевой сайт.** GitHub → **Pull requests → New** → `main ← dev`. Список коммитов — то, что есть на тестовом, но ещё не на боевом. Пустой — версии одинаковые.

## Где теперь править тексты и цены

**Только в админке боевого сайта:** https://car-on-time.ru/admin.

Правки в админке тестового сайта на боевой больше **не попадают**. Тестовый сайт — площадка для кода.

## Освежить тестовый сайт боевыми данными

Иногда нужно проверить правку на настоящих машинах и ценах. Копируем **вниз**:

```bash
# 1. копия на боевом
ssh u1111111@server111.hosting.reg.ru "cd car-on-time && /opt/php/8.4/bin/php artisan backup:database"

# 2. через компьютер — на тестовый
scp "u1111111@server111.hosting.reg.ru:car-on-time/storage/backups/db-*.sql.gz" ~/Perenos/
scp ~/Perenos/db-ДАТА.sql.gz u2222222@server222.hosting.reg.ru:car-on-time-dev/storage/backups/

# 3. на тестовом — загрузить и СРАЗУ выключить интеграции
ssh u2222222@server222.hosting.reg.ru
cd car-on-time-dev
gunzip -c storage/backups/db-ДАТА.sql.gz | mysql -u u2222222_dev -p u2222222_dev
/opt/php/8.4/bin/php artisan integrations:disable
/opt/php/8.4/bin/php artisan queue:clear
/opt/php/8.4/bin/php artisan optimize:clear
exit
```

> В боевой копии — **телефоны и имена клиентов** (персональные данные по 152-ФЗ). Храните такую копию на тестовом сайте только пока она нужна, не пересылайте её и удалите `~/Perenos` после работы.

Ключи интеграций на тестовом сайте не расшифруются (другой `APP_KEY`) — это защита: тестовый сайт не сможет написать настоящему клиенту.

## Резервные копии

Боевой сайт делает копию базы **сам**: каждую ночь в 03:30 и перед каждой выкладкой. Хранит последние 14 в `storage/backups`.

Раз в неделю скачивайте к себе копию базы и фото:

```bash
scp "u1111111@server111.hosting.reg.ru:car-on-time/storage/backups/db-*.sql.gz" ~/Backups/
rsync -avz u1111111@server111.hosting.reg.ru:car-on-time/storage/app/public/ ~/Backups/photos/
```

Подробно, в том числе восстановление из копии, — **Для разработчиков → Резервные копии и откат**.

## Если после обновления что-то сломалось

1. **Не паникуйте:** копия базы сделана перед выкладкой.
2. Быстрый откат кода: GitHub → **Actions → «Выкладка на хостинг» → Run workflow** → среда `production` → в поле «Что выложить» номер последнего рабочего коммита.
3. Потом спокойно исправьте и выпустите заново через `dev`.

## Раз в месяц

- [ ] В админке **Интеграции → Журнал обмена** нет повторяющихся ошибок.
- [ ] Ночные копии появляются (`ls storage/backups` на сервере).
- [ ] Свежая копия скачана к себе.
- [ ] Место на хостинге не кончается (панель reg.ru → «Информация»).
