# Три среды: компьютер, тестовый и боевой сайт

С этого урока начинается блок **«Работа с продом»**. Прод (production) — это боевой сайт, на который приходят настоящие клиенты.

## Три копии одного сайта

У нас одна и та же программа работает в трёх местах:

| | Ваш компьютер | Тестовый сайт | Боевой сайт |
|---|---|---|---|
| Адрес | `http://rentacar.test` | `https://dev.void-web.ru` | `https://car-on-time.ru` |
| Зачем | делать правки | показать клиенту и проверить на настоящем хостинге | работать с клиентами |
| Где | Laravel Herd | reg.ru, аккаунт №2 | reg.ru, аккаунт №1 |
| Среда в GitHub | — | `staging` | `production` |
| `APP_ENV` в `.env` | `local` | `staging` | `production` |
| База | своя, `car_on_time` | своя, например `u2222222_dev` | своя, например `u1111111_car` |
| Картинки | своя папка | своя папка | своя папка |
| Интеграции (CRM, SMS) | выключены | выключены | включены |
| Поисковики | не видят | не видят | индексируют |
| Яндекс Метрика | нет | нет | есть |

Это как ресторан: **своя кухня дома** (компьютер), **пробный ужин для хозяина** (тестовый сайт) и **открытый для гостей зал** (боевой сайт). Рецепты одни и те же, а продукты на каждой кухне свои.

## Что одинаковое, а что у каждого своё

**Одинаковое — код.** Он хранится в GitHub и попадает на оба сайта одинаково: GitHub его собирает и заливает сам.

**У каждой копии своё** — то, чего **нет** в GitHub:

1. **Файл `.env`** — настройки конкретной копии: адрес сайта, имя и пароль базы, ключ шифрования `APP_KEY`. Лежит в папке сайта на сервере, создаётся руками один раз.
2. **База данных** — машины, цены, заявки, тексты из админки, сотрудники.
3. **Загруженные файлы** — фото машин, обложки статей, документы клиентов. Лежат в `storage/app/public` (публичные) и `storage/app/private` (документы клиентов).

## «Ведь база на проде будет под другим именем?»

Да, и **это нормально**. На reg.ru имя базы всегда начинается с логина хостинга: `u1111111_car`, `u2222222_dev`. Сайт узнаёт имя базы **только** из своего `.env`:

```dotenv
DB_DATABASE=u2222222_dev
DB_USERNAME=u2222222_dev
DB_PASSWORD=пароль-из-панели
```

Внутри копии базы (файла `.sql`) имени базы **нет** — там только таблицы и строки. Поэтому копию из базы `car_on_time` можно загрузить в базу `u1111111_car`: таблицы просто окажутся в новой базе.

## Что меняет `APP_ENV`

| | `local` / `staging` | `production` |
|---|---|---|
| `robots.txt` | «никому не индексировать» | правила из админки + карта сайта |
| Яндекс Метрика | не подключается | подключается |
| Отправка в IndexNow | нет | да (если включена) |
| Строгий HTTPS (HSTS) | нет | да |
| `integrations:disable` | выключает сразу | спрашивает «точно?» |

Поэтому тестовый сайт **не попадёт в Яндекс как дубль** и не испортит статистику Метрики.

## Главное правило

> **Код идёт вверх, данные идут вниз.**
>
> Код: компьютер → тестовый сайт → боевой сайт.
> Данные: боевой сайт → тестовый сайт → компьютер.

Одно исключение — **первый запуск**: пока боевого сайта ещё нет, клиент наполняет тестовый, и один раз его данные переезжают на боевой. После запуска данные на боевой сайт больше **никогда** не копируются: там уже настоящие заявки.
