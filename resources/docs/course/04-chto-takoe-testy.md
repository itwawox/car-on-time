# Что такое тесты и как они работают

## Зачем они нужны

Представьте, что после каждого изменения на сайте кто-то вручную проходит 200 проверок: открывает каталог, отправляет заявку, вводит промокод, проверяет SMS, заходит в админку менеджером… Это часы работы, и человек обязательно что-то пропустит.

**Автотест** — это маленькая программа, которая делает одну такую проверку за доли секунды. У нас их больше 190, все вместе проходят примерно за 10 секунд.

Главная польза: вы меняете одно место, а тест замечает, что **сломалось другое**. Например, правили цвет кнопки, а случайно задели форму заявки.

## Кто их запускает

- **Pest** — программа-запускалка тестов. Он находит все файлы в папке `tests`, по очереди выполняет тесты и показывает, что прошло, а что нет.
- **PHPUnit** — более старая запускалка, на ней построен сам Pest. Часть наших тестов написана в её стиле (классы с `public function test_...`), и Pest запускает их без переделки. **Новые тесты пишем в стиле Pest.**

## Живой сайт не затрагивается

Перед каждым тестом создаётся **временная пустая база в памяти** (SQLite). Тест сам кладёт туда нужные машины и заявки, проверяет, и база исчезает. Ваши данные в Herd и боевой сайт тесты не трогают.

Внешние сервисы тоже не вызываются по-настоящему: вместо Битрикс24, SMS и ЮKassa подставляются **подмены**, которые отвечают как настоящие. Подробно — в уроке «Пишем свой тест».

## Два вида тестов

| Вид | Папка | Что проверяет | Пример |
|---|---|---|---|
| **Feature** (функциональный) | `tests/Feature` | как сайт работает целиком: открыть страницу, отправить форму, зайти в админку | «Статьи есть в подвале и нет в шапке» |
| **Unit** (модульный) | `tests/Unit` | одну маленькую функцию, без базы и страниц | «номер 8 978 … превращается в +7978…» |

Почти все наши тесты — Feature.

## Из чего состоит тест

Любой тест — три шага:

1. **Подготовили** — создали то, что нужно для проверки (статью, машину, настройку).
2. **Сделали** — открыли страницу, отправили форму, запустили команду.
3. **Проверили** — то, что получилось, совпадает с ожидаемым.

## Разбор настоящего теста

Файл `tests/Feature/HeaderNavTest.php`. Владелец попросил убрать «Статьи» из меню в шапке и оставить в подвале. Тест следит, чтобы это не вернулось:

```php
it('shows articles link in the footer but not in the header or mobile menu', function () {
    // 1. Подготовили: одна опубликованная статья (без статей ссылки нет вообще)
    Article::query()->create(['slug' => 'aeroport', 'title' => 'Как взять авто в аэропорту', 'content' => '<p>Текст</p>', 'is_published' => true, 'published_at' => now()->subMinute()]);

    // 2. Сделали: открыли главную страницу и взяли её HTML
    $html = $this->get('/')->assertOk()->getContent();

    $link = 'href="'.route('articles').'"';
    $nav = fn (string $label): string => Str::before(Str::after($html, 'aria-label="'.$label.'"'), '</nav>');

    // 3. Проверили: в меню шапки и мобильном меню ссылки нет, в подвале — есть
    expect($nav('Основное меню'))->not->toContain($link)
        ->and($nav('Мобильное меню'))->not->toContain($link)
        ->and($nav('Информация'))->toContain($link);
});
```

По строкам:

- `it('…', function () { … })` — объявление теста. В кавычках — название на английском: «показывает ссылку на статьи в подвале, но не в шапке». Его Pest выведет в отчёте.
- `Article::query()->create([...])` — положили статью во временную базу.
- `$this->get('/')` — «открыли» главную страницу, как браузер, только без браузера.
- `->assertOk()` — первая проверка: страница открылась (код 200, а не ошибка 500 или 404).
- `$nav(...)` — вырезали из HTML кусок одного меню.
- `expect(...)->not->toContain(...)` — «ожидаю, что тут **нет** такой ссылки». `->toContain` без `not` — «ожидаю, что **есть**».

## Как запустить

```bash
./vendor/bin/pest                                  # все тесты
./vendor/bin/pest tests/Feature/HeaderNavTest.php  # один файл
./vendor/bin/pest --filter="articles"              # тесты, в названии которых есть слово
```

## Как читать результат

Всё хорошо:

```text
   PASS  Tests\Feature\HeaderNavTest
  ✓ it shows articles link in the footer but not in the header or mobile menu   0.28s

  Tests:    1 passed (4 assertions)
```

- `PASS` и зелёная галочка `✓` — тест прошёл.
- `4 assertions` — внутри было 4 проверки (`assertOk` и три `expect`).

Что-то сломалось:

```text
   FAIL  Tests\Feature\HeaderNavTest
  ⨯ it shows articles link in the footer but not in the header or mobile menu

  Expecting '…' not to contain 'href="https://rentacar.test/stati"'.

  at tests/Feature/HeaderNavTest.php:14
```

- `FAIL` и крестик `⨯` — тест упал.
- Следующая строка — **что именно** не так: «ожидал, что тут не будет ссылки на /stati, а она есть».
- `at tests/Feature/HeaderNavTest.php:14` — файл и **номер строки** с проверкой, которая не прошла.

> Упавший тест — это не беда, а подсказка. Он поймал проблему у вас на компьютере, а не у клиента на сайте.

## Попробуйте сами

1. Запустите `./vendor/bin/pest tests/Feature/HeaderNavTest.php` — должно быть `1 passed`.
2. Откройте `resources/views/layouts/app.blade.php`, в массиве `$nav` верните строку со «Статьями» (скопируйте строку с «Акциями» и поменяйте слова).
3. Запустите тест снова — он упадёт и покажет строку 14.
4. Отмените изменение (`git checkout resources/views/layouts/app.blade.php`) — тест снова зелёный.
