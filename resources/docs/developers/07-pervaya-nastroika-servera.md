# Первая настройка хостинга reg.ru

Делается **один раз**. Дальше сайт обновляется сам после мержа в `main`. Ниже в примерах логин хостинга — `u1234567`; подставьте свой (он в письме от reg.ru и в панели управления хостингом).

## 1. Панель хостинга: PHP, база, SSH

1. **Версия PHP — 8.4.** Панель хостинга → «Сайты» (или «PHP») → для `car-on-time.ru` выберите PHP 8.4. Библиотеки сайта не работают на более старых версиях.
2. **База данных MySQL.** Панель → «Базы данных» → создать. Запишите имя базы, пользователя и пароль.
3. **Доступ по SSH.** Панель → «Доступ по SSH» (или в личном кабинете reg.ru → услуга хостинга) → включить. Адрес сервера для подключения указан там же, например `server123.hosting.reg.ru`.

Проверка — с вашего компьютера в Терминале:

```bash
ssh u1234567@server123.hosting.reg.ru
/opt/php/8.4/bin/php -v       # должно показать PHP 8.4
which rsync mysqldump gzip     # все три должны найтись
exit
```

На reg.ru команда `php` без пути может запускать старую версию — **всегда пишите полный путь** `/opt/php/8.4/bin/php`.

## 2. SSH-ключ, чтобы GitHub мог заливать файлы

На своём компьютере создайте отдельный ключ для выкладки (без пароля — просто нажмите Enter на вопросы):

```bash
ssh-keygen -t ed25519 -f ~/.ssh/car-on-time-deploy -C "github-deploy"
ssh-copy-id -i ~/.ssh/car-on-time-deploy.pub u1234567@server123.hosting.reg.ru
```

Вторая команда один раз спросит пароль хостинга и добавит ключ. Проверьте, что вход без пароля работает:

```bash
ssh -i ~/.ssh/car-on-time-deploy u1234567@server123.hosting.reg.ru "echo ok"
```

## 3. Секреты в GitHub

Сайт выкладывается в две среды, и у каждой **свои** секреты:

- `staging` — тестовый сайт (например, `dev.void-web.ru`);
- `production` — боевой `car-on-time.ru`.

https://github.com/itwawox/car-on-time → **Settings → Environments** → **New environment** → имя `staging` или `production` (строчными, как здесь).

В среде: **Environment secrets → Add environment secret**, по одному:

| Имя | Значение (пример) |
|---|---|
| `DEPLOY_HOST` | `server123.hosting.reg.ru` |
| `DEPLOY_USER` | `u1234567` |
| `DEPLOY_PATH` | `/var/www/u1234567/data/car-on-time` |
| `DEPLOY_PHP` | `/opt/php/8.4/bin/php` |
| `DEPLOY_SSH_KEY` | содержимое файла `~/.ssh/car-on-time-deploy` (закрытый ключ, **без** `.pub`). Показать: `cat ~/.ssh/car-on-time-deploy` |

Там же **Environment variables → Add environment variable**: `DEPLOY_URL` = адрес сайта этой среды, например `https://car-on-time.ru`. Выкладка сверяет его с `APP_URL` в `.env` на хостинге и **останавливается**, если они не совпадают. Так тестовая версия не попадёт на боевой сайт из-за перепутанных секретов.

И один раз для всего репозитория: **Settings → Secrets and variables → Actions → Variables → New repository variable**: `DEPLOY_ENABLED` = `true`. Пока этой переменной нет, GitHub только проверяет тесты и ничего не выкладывает.

> Если раньше секреты `DEPLOY_*` заводились в **Secrets and variables → Actions** (для всего репозитория) — удалите их оттуда и заведите в средах. Иначе среда, где вы забыли секрет, возьмёт его у репозитория.

Секреты никто не видит, даже вы после сохранения — это нормально.

Подробный разбор, как поднять тестовый сайт и потом переехать на боевой, — **Документация → Курс**, уроки про прод.

## 4. Первая выкладка файлов

GitHub → **Actions → «Выкладка на хостинг» → Run workflow** → выберите среду → **Run workflow**. Первый запуск остановится с сообщением «нет файла .env» — это ожидаемо: файлы уже залиты, осталось настроить сайт.

## 5. Файл `.env` на хостинге

```bash
ssh u1234567@server123.hosting.reg.ru
cd ~/car-on-time
cp .env.example .env
nano .env
```

Заполните (стрелки — перемещение, Ctrl+O и Enter — сохранить, Ctrl+X — выйти):

```dotenv
APP_ENV=production
APP_DEBUG=false                    # обязательно false: иначе при ошибке посетитель увидит пароли
APP_URL=https://car-on-time.ru      # совпадает с DEPLOY_URL среды; для тестового сайта — его адрес и APP_ENV=staging

DB_HOST=localhost
DB_DATABASE=u1234567_car           # из шага 1
DB_USERNAME=u1234567_car
DB_PASSWORD=…

QUEUE_CONNECTION=database
CACHE_STORE=database
SESSION_DRIVER=database
```

Затем:

```bash
/opt/php/8.4/bin/php artisan key:generate
/opt/php/8.4/bin/php artisan user:owner ваш@email.ru --name="Иван"
exit
```

Вторая команда создаст владельца админки и один раз покажет пароль — сохраните его.

> ⚠️ `APP_KEY` (его записала команда `key:generate`) после запуска **не меняйте**: ключи интеграций зашифрованы им. Сохраните копию `.env` в надёжном месте (менеджер паролей).

Ключи Битрикс24, SMS и Telegram в `.env` не нужны — они вводятся в админке, **Интеграции → Интеграции**.

После этого снова запустите выкладку (**Actions → Run workflow**) — она пройдёт до конца.

## 6. Корневая папка сайта → `public`

Сайт должен открываться из папки `public`, а не из корня проекта (иначе будут видны служебные файлы).

**Способ 1 (панель):** «Сайты» → `car-on-time.ru` → изменить → **Корневая директория** → `/var/www/u1234567/data/car-on-time/public`.

**Способ 2 — ссылка вместо папки (если панель не даёт менять корневую директорию).** Панель открывает сайт из папки `~/www/имя-домена`. Эту папку переименовываем и на её месте создаём **символическую ссылку** — «ярлык» на папку `public` нашего сайта. Панель ничего не замечает и открывает сайт через ярлык.

Создать ссылку (выкладка к этому моменту уже должна была залить сайт, то есть папка `public` существует):

```bash
ssh u1234567@server123.hosting.reg.ru
cd ~/www
mv car-on-time.ru car-on-time.ru.old             # старую папку не удаляем — на случай отката
ln -s ~/car-on-time/public car-on-time.ru        # ярлык: имя домена → public сайта
ls -la | grep car-on-time.ru                     # проверка
exit
```

Проверка должна показать стрелку:

```text
car-on-time.ru -> /var/www/u1234567/data/car-on-time/public
car-on-time.ru.old
```

То же одной строкой — надёжнее: если вход по SSH не удастся, ничего не выполнится на вашем компьютере по ошибке:

```bash
ssh u1234567@server123.hosting.reg.ru 'cd ~/www && mv car-on-time.ru car-on-time.ru.old && ln -s ~/car-on-time/public car-on-time.ru && ls -la | grep car-on-time.ru'
```

- `ln -s КУДА ИМЯ` — сначала **куда** ведёт ярлык, потом **имя** ярлыка. Перепутать порядок — частая ошибка.
- Путь к `public` — тот же, что в секрете `DEPLOY_PATH`, плюс `/public`. Если код лежит внутри `www` (например, `~/www/car-on-time-dev`), ярлык — `ln -s ~/www/car-on-time-dev/public dev.void-web.ru`.
- Выкладка ярлык не трогает: она обновляет файлы внутри папки сайта, а ярлык указывает на неё.

Удалить ссылку и вернуть как было:

```bash
ssh u1234567@server123.hosting.reg.ru
cd ~/www
rm car-on-time.ru                    # удаляет ТОЛЬКО ярлык, файлы сайта не трогает
mv car-on-time.ru.old car-on-time.ru
exit
```

> ⚠️ Для удаления ярлыка пишите имя **без** `/` на конце: `rm car-on-time.ru`. Не используйте `rm -r` и `rm -rf` — с `/` на конце они могут удалить содержимое папки, на которую ведёт ярлык, то есть сам сайт.

Перенаправить ярлык на другую папку (например, при переезде сайта в новую папку): `ln -sfn ~/новая-папка/public car-on-time.ru`.

Когда сайт открывается и работает, папку `.old` можно удалить: `rm -r ~/www/car-on-time.ru.old` (это обычная папка, не ярлык).

Там же в панели включите **SSL-сертификат** (бесплатный Let's Encrypt) и **перенаправление на HTTPS**. Выпускайте сертификат **после** создания ссылки. Если Let's Encrypt не может проверить домен, пришлите текст ошибки разработчику.

## 7. Планировщик CRON — обязательно

Без него **не работают**: отправка заявок в Битрикс24, SMS клиентам, напоминания о просроченных заявках, ночные копии базы.

Панель хостинга → **Планировщик CRON → Создать задание**:

- **Команда:** `/opt/php/8.4/bin/php /var/www/u1234567/data/car-on-time/artisan schedule:run`
- **Расписание:** каждую минуту (`* * * * *`)

Проверка по SSH: `cd ~/car-on-time && /opt/php/8.4/bin/php artisan schedule:list`. Через пару минут в админке **Интеграции → Журнал обмена** начнут появляться записи, если включены интеграции.

## Если у вас панель cPanel или Plesk

Пути другие: в cPanel папка сайта обычно `/var/www/u1234567/public_html/…`, в Plesk — `/var/www/vhosts/u1234567.plsk.regruhosting.ru/httpdocs/…`. Путь к PHP тот же: `/opt/php/8.4/bin/php`. Если сомневаетесь — поддержка reg.ru подскажет путь к домашней папке и включит SSH.

## Если сайт переедет на VPS

Для VPS готов конфиг `deploy/nginx-car-on-time.conf` (HTTPS, сжатие, кэш статики). На обычном хостинге он не нужен: там работает Apache и файл `public/.htaccess`.
