# Изменения базы данных (миграции)

## Пример: добавили поле «Цвет» в карточку машины

Чтобы у машины появилось новое поле, в базе должна появиться новая **колонка**. Это делает миграция:

```bash
php artisan make:migration add_color_to_cars_table
```

Laravel создаст файл в `database/migrations`, в нём пишем:

```php
public function up(): void
{
    Schema::table('cars', function (Blueprint $table) {
        $table->string('color', 40)->nullable();   // nullable — у старых машин поле пустое, и это нормально
    });
}

public function down(): void
{
    Schema::table('cars', function (Blueprint $table) {
        $table->dropColumn('color');
    });
}
```

Дальше: добавить поле в форму админки (`app/Filament/Resources/Cars/CarResource.php`) и вывести на сайте. Локально применить: `php artisan migrate`. Потом коммит → пуш → мерж в `main` — выкладка сама выполнит на хостинге `php artisan migrate --force`.

**Что будет с машинами на боевом сайте?** Ничего плохого: у всех появится пустое поле «Цвет», остальное не тронется. Заполнить его можно в админке.

## Как перенести данные, а не только структуру

Если нужно, чтобы на боевом сайте сразу появились какие-то данные (например, новый раздел FAQ, новые точки выдачи, исправленные цены), есть два пути:

1. **Руками в админке боевого сайта** — проще и надёжнее для разовых правок.
2. **«Миграция с данными»** — миграция, которая не меняет структуру, а добавляет или правит записи. Так уже сделаны `2026_09_27_100000_fix_location_prices_and_names.php`, `2026_09_26_180000_rebuild_faq.php`. Подходит, когда данных много или их нужно одинаково завести на нескольких сайтах. Пишите такие миграции осторожно: они не должны затирать то, что менеджеры уже поправили в админке.

## ⚠️ Команды, которые НЕЛЬЗЯ запускать на хостинге

| Команда | Что сделает |
|---|---|
| `php artisan migrate:fresh` | **Удалит все таблицы** — все машины, заявки, пользователей — и создаст пустые. |
| `php artisan migrate:refresh` / `migrate:reset` | Откатит все миграции — тоже потеря данных. |
| `php artisan db:wipe` | Удалит всё из базы. |
| `php artisan db:seed` | Может залить тестовые данные поверх настоящих. |

На своём компьютере это можно — локальная база учебная.

## Уже выполненную миграцию не редактируем

Если миграция уже на боевом сайте, Laravel её повторно не запустит — правки в старом файле ни на что не повлияют. Нужна новая миграция с исправлением.

## Посмотреть, какие миграции применены

```bash
php artisan migrate:status                                            # локально
ssh u1234567@server123.hosting.reg.ru "cd car-on-time && /opt/php/8.4/bin/php artisan migrate:status"   # на хостинге
```
