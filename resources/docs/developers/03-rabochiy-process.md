# Рабочий процесс: от правки до боевого сайта

Схема всегда одна и та же:

```
ваш компьютер  ──коммит──▶  ветка  ──пуш──▶  GitHub  ──Pull Request + мерж в main──▶  GitHub Actions сам выкладывает на reg.ru
(rentacar.test)                                                                        (car-on-time.ru)
```

## Шаг 0. Один раз: подготовить компьютер

1. Установить **Laravel Herd** (https://herd.laravel.com) — он поднимает сайт на http://rentacar.test.
2. Установить **Git** (на Mac уже есть) и, по желанию, **GitHub Desktop** (https://desktop.github.com) — окно с кнопками вместо команд.
3. Войти в GitHub в терминале: `gh auth login` (или войти в GitHub Desktop).

## Шаг 1. Перед началом работы — забрать свежий код

```bash
cd ~/Herd/rentacar
git checkout main
git pull
composer install
npm install
php artisan migrate
```

Последние три команды нужны, если кто-то другой добавил библиотеки или миграции. Лишний раз их запускать не страшно.

## Шаг 2. Создать ветку под задачу

```bash
git checkout -b feature/cvet-v-kartochke
```

Название — любое понятное, латиницей, без пробелов.

## Шаг 3. Сделать изменения и проверить локально

- Смотрите результат на http://rentacar.test.
- Если меняли стили или скрипты — `npm run dev` (пересобирает на лету) или `npm run build`.
- Прогоните тесты: `php artisan test`. Всё должно быть зелёным. Что это и как писать свои — раздел «Автотесты».

## Шаг 4. Сохранить (коммит) и отправить (пуш)

```bash
git status                 # что изменилось
git add -A                 # взять все изменения
git commit -m "Карточка машины: поле «Цвет»"
git push -u origin feature/cvet-v-kartochke
```

В GitHub Desktop то же самое: слева отметить файлы → внизу написать название → **Commit** → **Push origin**.

## Шаг 5. Pull Request и мерж в main

1. Откройте https://github.com/itwawox/car-on-time — появится жёлтая плашка **Compare & pull request**. Нажмите.
2. Проверьте список изменений (вкладка **Files changed**).
3. Нажмите **Merge pull request** → **Confirm merge**.

Теперь изменения в `main`, и GitHub **сам** начинает выкладку на хостинг (если она настроена, раздел «Первая настройка хостинга reg.ru»). На Pull Request заранее видно, прошли ли тесты: зелёная галочка — можно вливать.

## Шаг 6. Проверить боевой сайт

Через 3–5 минут после мержа загляните во вкладку **Actions**: «Выкладка на хостинг» должна быть с зелёной галочкой. Откройте https://car-on-time.ru и проверьте изменения. Подробно — следующий раздел.

## Если работаете вдвоём в одной папке на одном компьютере

Git не разделяет людей в одной папке: у вас общие файлы. Договоритесь, кто сейчас правит, или каждый работает в своей копии (`git worktree add ../rentacar-2 -b моя-ветка`). Коммитьте только свои файлы: `git add путь/к/файлу`, а не `git add -A`.

## Чего не делать

- Не коммитить файл `.env`, копии базы, пароли и ключи — репозиторий **публичный**, его видят все.
- Не делать `git push --force` в `main`.
- Не править код прямо на хостинге — следующая выкладка затрёт правку.
