# Резервные копии и откат

Во всех командах ниже `u1234567` и `server123.hosting.reg.ru` — ваши логин и сервер reg.ru, `php` — это `/opt/php/8.4/bin/php`.

## Резервные копии базы

- Делаются **автоматически каждую ночь в 03:30** (нужен настроенный CRON) и **перед каждой выкладкой**.
- Лежат на хостинге в `~/car-on-time/storage/backups`, файлы вида `db-2026-09-27_03-30-00.sql.gz`. Хранятся последние 14.
- Сделать копию вручную:
  ```bash
  ssh u1234567@server123.hosting.reg.ru "cd car-on-time && /opt/php/8.4/bin/php artisan backup:database"
  ```
- Копии содержат телефоны клиентов — в GitHub они не попадают (папка в `.gitignore`).

У reg.ru есть и свои резервные копии хостинга (панель → «Резервные копии»), но полагаться только на них не стоит.

**Храните копии не только на хостинге.** Раз в неделю скачивайте свежую к себе:

```bash
scp "u1234567@server123.hosting.reg.ru:car-on-time/storage/backups/db-*.sql.gz" ~/Backups/
```

Фото машин тоже стоит копировать (`storage/app/public`) — см. раздел «Файлы».

## Откатить код (после выкладки что-то сломалось)

**Способ 1 — выложить прошлую версию (быстро):**

1. GitHub → вкладка **Commits** → найдите последний рабочий коммит, скопируйте его номер (например, `1df2c90`).
2. **Actions → «Выкладка на хостинг» → Run workflow** → в поле «Что выложить» вставьте номер → **Run workflow**.
3. Через 3–5 минут на сайте прошлая версия. Спокойно исправьте ошибку и влейте исправление в `main` — выложится уже оно.

**Способ 2 — отменить изменения в GitHub (правильно):** на странице влитого Pull Request нажмите **Revert** → появится новый Pull Request, отменяющий изменения → **Merge**. GitHub выложит сайт без них.

⚠️ Откат кода **не откатывает базу**. Если выкладка добавила колонки, они останутся — старому коду это обычно не мешает.

## Откатить базу из копии (крайний случай)

Если миграция испортила данные. **Всё, что появилось после копии (новые заявки), пропадёт** — сначала сделайте свежую копию текущего состояния.

```bash
ssh u1234567@server123.hosting.reg.ru
cd car-on-time
/opt/php/8.4/bin/php artisan backup:database          # копия «как есть сейчас»
ls storage/backups                                    # выбрать нужную копию
/opt/php/8.4/bin/php artisan down
gunzip -c storage/backups/db-2026-09-27_03-30-00.sql.gz | mysql -u ПОЛЬЗОВАТЕЛЬ_БАЗЫ -p ИМЯ_БАЗЫ
/opt/php/8.4/bin/php artisan up
```

Имя и пользователь базы — в файле `.env` на хостинге (`DB_DATABASE`, `DB_USERNAME`). Базу можно восстановить и через phpMyAdmin в панели reg.ru → «Импорт» (файл предварительно распаковать).

## Посмотреть ошибки сайта

```bash
ssh u1234567@server123.hosting.reg.ru "tail -n 100 car-on-time/storage/logs/laravel.log"
```
