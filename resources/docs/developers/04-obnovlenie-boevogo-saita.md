# Обновление боевого сайта (деплой)

Сайт работает на **обычном хостинге reg.ru** (не VPS). На таком хостинге нет Node.js для сборки стилей и мало ресурсов для Composer, поэтому сайт **собирает GitHub**, а на хостинг заливаются уже готовые файлы.

## Как это работает (после разовой настройки)

```
вы: мерж Pull Request в main
        │
        ▼
GitHub Actions (сам, 3–5 минут):
  1. прогоняет тесты — если что-то сломано, выкладка не начнётся
  2. собирает сайт: библиотеки PHP, стили и скрипты
  3. на хостинге: копия базы → режим «Сайт обновляется»
  4. заливает файлы на reg.ru по SSH
  5. на хостинге: миграции базы, кэши, перезапуск фоновых задач → сайт открыт
```

**То есть обновление боевого сайта = мерж Pull Request в `main`.** Больше ничего делать не нужно.

## Две среды: тестовый и боевой сайт

| Среда | Сайт | Когда выкладывается сама |
|---|---|---|
| `staging` | тестовый, например `dev.void-web.ru` | после пуша в ветку `dev` |
| `production` | `car-on-time.ru` | после мержа в `main` |

Обычный путь правки: ветка → пуш в `dev` (или слить в неё свою ветку) → проверить на тестовом сайте → Pull Request в `main` → боевой сайт.

```bash
git checkout dev && git pull
git merge fix/moya-pravka
git push                 # через 3–5 минут правка на тестовом сайте
```

Разовая настройка (ключ SSH и секреты в GitHub) описана в разделе «Первая настройка хостинга reg.ru».

## Как следить за выкладкой

1. Откройте https://github.com/itwawox/car-on-time → вкладка **Actions**.
2. Сверху — последний запуск «Выкладка на хостинг». Жёлтый кружок — идёт, зелёная галочка — готово, красный крестик — ошибка.
3. Нажмите на запуск → на шаг с крестиком — там текст ошибки.

Если упал шаг «Тесты», сайт **не трогался** — исправьте код и влейте снова. Если упала сама выкладка — скрипт включит сайт обратно; копия базы на хостинге лежит в `storage/backups`.

## Выложить вручную или повторить

**Actions → «Выкладка на хостинг» → Run workflow** → выберите среду (`staging` или `production`) → **Run workflow**. В поле «Что выложить» можно указать ветку или номер коммита — так выкладывают старую версию для отката (раздел «Резервные копии и откат») или показывают любую ветку на тестовом сайте.

## Выложить со своего компьютера (запасной путь)

Если GitHub Actions недоступен:

1. Один раз: скопируйте `deploy/.env.deploy.example` в `deploy/.env.deploy` и впишите свои данные reg.ru и `DEPLOY_URL` — адрес сайта (файл в GitHub не попадает). Для тестового сайта заведите второй файл, `deploy/.env.deploy.dev`, и выкладывайте так: `DEPLOY_ENV_FILE=deploy/.env.deploy.dev bash deploy/release.sh`. Все файлы `deploy/.env.deploy*`, кроме примера, git не видит.
2. Каждый раз:
   ```bash
   cd ~/Herd/rentacar
   git checkout main && git pull
   composer install --no-dev --optimize-autoloader
   npm ci && npm run build
   bash deploy/release.sh
   composer install          # вернуть инструменты разработки для локальной работы
   ```

## Что делают скрипты

| Файл | Где выполняется | Что делает |
|---|---|---|
| `.github/workflows/tests.yml` | GitHub | тесты на каждом Pull Request |
| `.github/workflows/deploy.yml` | GitHub | после мержа в `main` (боевой) или пуша в `dev` (тестовый): тесты → сборка → `deploy/release.sh` |
| `deploy/release.sh` | GitHub или ваш компьютер | сверка адреса сайта (`DEPLOY_URL` = `APP_URL` на хостинге) → копия базы и режим обслуживания → заливка файлов через `rsync` → запуск `remote-finish.sh` |
| `deploy/remote-finish.sh` | хостинг | `migrate --force`, `storage:link`, кэши, `queue:restart`, `up` |

При заливке **не трогаются**: файл `.env`, папка `storage` (загруженные фото, логи, копии базы), ссылка `public/storage`. Файлы, удалённые из кода, удаляются и с хостинга.

## Как понять, какая версия сейчас на сайте

**Внизу любой страницы админки** — строка вида «Версия 7c6caea · ветка dev · выложена 15.10.2026 18:04 · сравнить с GitHub». Её пишет выкладка: `deploy/release.sh` перед заливкой создаёт файл `version.json` (коммит, ветка, время), в GitHub он не хранится.

- **«сравнить с GitHub»** открывает сравнение выложенного коммита с веткой. «There isn't anything to compare» или «identical» — на сайте самая свежая версия ветки. Список коммитов — они есть в GitHub, но ещё не выложены.
- **«Версия не записана»** — копия на компьютере или сайт выложен не скриптом выкладки.

Ещё способ: вкладка **Actions** → последний зелёный запуск «Выкладка на хостинг» нужной среды — в нём название и номер коммита.
