# Частые вопросы и проблемы

**Кто-то поправил файл прямо на хостинге — что будет?**
Следующая выкладка заменит его версией из GitHub, правка пропадёт. Если правка нужна — повторите её локально, закоммитьте и влейте в `main`.

**Выкладка в Actions красная.**
Нажмите на запуск → на шаг с крестиком. «Тесты» — сломан код, сайт не трогался. «SSH-ключ» или «Выкладка» с `Permission denied` — неверный ключ или логин в секретах (раздел «Первая настройка хостинга reg.ru», шаги 2–3). «нужен PHP 8.4» — поправьте секрет `DEPLOY_PHP` или версию PHP в панели. «нет файла .env» — шаг 5 первой настройки. «Остановлено: на хостинге APP_URL=…» — секреты среды указывают не на тот сервер или в `.env` на хостинге другой `APP_URL`: сравните переменную `DEPLOY_URL` среды (Settings → Environments) и `APP_URL` в `.env`.

**Выкладка в Actions серая или её нет.**
Не задана переменная `DEPLOY_ENABLED = true` (Settings → Secrets and variables → Actions → Variables).

**После обновления на сайте ошибка 500.**
Посмотрите ошибку: `ssh u1234567@server123.hosting.reg.ru "tail -n 50 car-on-time/storage/logs/laravel.log"`. Частые причины: не заполнен `.env`, в панели выбрана не та версия PHP, упала миграция. Если непонятно — выложите прошлую версию (раздел «Резервные копии и откат»).

**Изменения в стилях не видны.**
На хостинге — выкладка пересобирает стили сама. Локально — `npm run build`. В браузере — обновите страницу с Shift (Cmd+Shift+R на Mac).

**Ошибка «Vite manifest not found».**
Не собраны стили: `npm run build`.

**Поменял текст в «Настройках сайта» локально, на боевом не поменялся.**
Это данные, а не код — поменяйте в админке боевого сайта (раздел «Как устроен сайт»).

**Загрузил фото машины локально — на боевом сайте его нет.**
Фото — это загруженные файлы, они не ездят через GitHub. Загрузите через админку боевого сайта.

**Не могу войти в админку на боевом сайте (ошибка 403).**
У пользователя должна быть роль и открытый доступ. Владелец выдаёт их в **Интеграции → Сотрудники**. Если владельца нет совсем: по SSH `cd ~/car-on-time && /opt/php/8.4/bin/php artisan user:owner ваш@email.ru`.

**Заявки не уходят в Битрикс24 / SMS не приходят.**
1) **Интеграции → Журнал обмена** — есть ли записи и какая ошибка. 2) Если записей нет — проверьте задание в «Планировщике CRON» панели reg.ru. 3) Кнопки «Проверить подключение» и «Тестовое SMS» на странице «Интеграции».

**Можно ли что-то сломать, открыв код?**
Нет — пока вы не влили изменения в `main`, боевой сайт не меняется. Локально откатить все свои правки: `git checkout -- .` (осторожно: несохранённые изменения пропадут).

**Репозиторий публичный — это нормально?**
Код может быть открытым, но в нём не должно быть секретов. `.env`, копии базы и ключи в `.gitignore`. Если хотите закрыть код от чужих глаз: GitHub → репозиторий → **Settings → General → Danger Zone → Change visibility → Private**. Выкладка продолжит работать: GitHub Actions заливает файлы на хостинг сам, хостингу доступ к GitHub не нужен.

**Как дополнить эту документацию?**
Разделы — обычные текстовые файлы в `resources/docs/developers` (формат Markdown). Номер в имени файла задаёт порядок, первая строка `# …` — название раздела. Правьте локально и выкатывайте, как любой код.
