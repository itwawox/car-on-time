# Качество кода: Pint и Larastan

Кроме тестов, у проекта ещё два автоматических «контролёра». Вместе с тестами они запускаются одной командой:

```bash
composer check
```

Её же запускает GitHub на каждом Pull Request. Подробно, с примерами — в **Документация → Курс**, уроки «Тесты», «Качество кода» и «Безопасность».

## Pint — форматирование

Приводит код к одному стилю: отступы, пробелы, порядок `use`, лишние импорты. Не меняет смысл кода.

```bash
./vendor/bin/pint          # исправить стиль во всех файлах
./vendor/bin/pint --test   # только проверить (так делает GitHub)
```

## Larastan — статический анализ

Читает код **не запуская его** и ищет ошибки: обращение к несуществующему полю, не тот тип данных, переменная, которой нет. Так найдён реальный баг: веса полей в «Настройках поиска» не применялись, потому что переменная `$weights` не передавалась внутрь функции.

```bash
./vendor/bin/phpstan
```

- Настройки — `phpstan.neon` (уровень строгости 5 из 10).
- `phpstan-baseline.neon` — список замечаний к коду, написанному **до** подключения Larastan. Новые туда **не добавляем** — исправляем. Со временем список должен уменьшаться.

## Заголовки безопасности

Каждую страницу сайт отдаёт с заголовками, которые защищают посетителей: запрет подмены типа файлов (`nosniff`), аккуратная передача адреса при переходах (`Referrer-Policy`), запрет встраивать сайт в чужие страницы (кроме Вебвизора Метрики), а на боевом сайте по HTTPS — `Strict-Transport-Security`. Админку встраивать нельзя никуда. Версия PHP не раскрывается.

Ставит их `App\Http\Middleware\SecurityHeaders` — внутри Laravel, поэтому работает на любом хостинге (раньше они были только в конфиге nginx, который на reg.ru не используется). Проверить на боевом сайте:

```bash
curl -sI https://car-on-time.ru/ | grep -iE "x-content|referrer|permissions|content-security|strict"
```
